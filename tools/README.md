# tools/

Scripts and subprojects supporting the CrystalOSD decomp workflow.

## Decomp workflow — ranked

### Golden path: objdiff loop (fully offline)

1. Pick target function (unmatched in `asm/<sub>/<func>.s`)
2. Analyze in Ghidra (`mcp__ghidra__decompile_function`)
3. Write C in `src/<sub>/<func>.c` (ee-gcc 2.9 quirks — see `reference/COMPILER_QUIRKS.md`)
4. `make all` — builds `build/target/<sub>/<func>.o` from asm and `build/base/<sub>/<func>.o` from C via `MATCH_CC=ee-gcc2.9-991111`
5. Open objdiff (generated by `tools/generate_objdiff.py`) — compare `.text` diff
6. Edit C, repeat step 4–5 until diff is zero
7. Flip splat subsegment from `asm` → `c` in `splat_config.yml`
8. `make elf && make verify` — must report byte-perfect match
9. Commit: `decomp(scope): match <func>`

### Fallback 1: decomp-permuter (brute-force, last-mile)

Use when the objdiff diff is small but no manual edit closes it.

```bash
./tools/permuter_import.sh <func> src/<sub>/<func>.c
cd tools/decomp-permuter && python3 ./permuter.py nonmatchings/<func> -j8
```

### Fallback 2: decomp.me API (collaboration / sharing)

Use for sharing progress with the wider decomp community or when wanting a hosted scratch.
No longer the daily matching driver.

```bash
python3 tools/decomp_match.py submit <func> asm/<sub>/<func>.s src/<sub>/<func>.c
python3 tools/decomp_match.py iterate <slug> src/<sub>/<func>.c
```

## Tools by purpose

### Decomp pipeline
| Tool | Role | Rank |
|------|------|------|
| `generate_objdiff.py` + `make all` | Build target+base .o for objdiff comparison | **Golden path** |
| `decomp-permuter/` | Brute-force permutation matcher | Fallback 1 |
| `decomp_match.py` | decomp.me API client — submit/iterate/extract | Fallback 2 |
| `permuter_import.sh` | Imports `<func> + <src>` into `decomp-permuter/nonmatchings/<func>/` | Fallback 1 helper |
| `transmuter/` | Cleans Ghidra stub noise (`uVar1`, `puVar2` → idiomatic C). **Stub cleaner only — does not match against ASM.** | Pre-processing |
| `run_batch_transmuter.sh` | Batch-cleans stubs in `src/stubs/<sub>/` | Pre-processing |

### Build / verify
| Tool | What it does |
|------|--------------|
| `split_functions.py` | Reads `symbol_addrs.txt`, emits per-function splat subsegments into `splat_config.yml` |
| `generate_objdiff.py` | Builds `objdiff.json` from current `src/` + `asm/` layout |
| `verify_elf.py` | Compares `build/OSDSYS.elf` vs original — section layout, headers, first byte differing |
| `progress.py` | Per-subsystem decomp progress report; supports `--json`, `--markdown`, `--crossref` |
| `commit_organizer.py` | Scans the working tree, groups changes by Conventional Commit (`type(scope)`), proposes one atomic commit per group. Modes: preview (default), `--interactive`, `--commit`, `--dry-run` |
| `wsl/build_verify.sh` | Canonical byte-perfect build on WSL: `configure.py -c` → restore committed asm → `patch_data_labels.py` → compile C with ee-gcc on native ext4 → `make elf` → verify sha1 |
| `wsl/patch_data_labels.py` | Inserts data glabels that the current splat run omits; required for the byte-perfect build |

### Misc / one-shots
| Tool | What it does |
|------|--------------|
| `patch_stubs.py` | Touches up Ghidra-emitted stubs (e.g. variable renames) |
| `test_api.py` | Minimal decomp.me API request — useful when diagnosing CF/header issues |
| `split_aligns.py` | Alignment analysis helper |
| `discover_core.json`, `graph_manifest.json` | Static manifests of which functions belong to which subsystem |

### Archived (tools/attic/)
| Tool | Status |
|------|--------|
| `attic/orchestrator/` | Archived. Former LLM-driven PLANNER/WORKER/JUDGE pipeline. Superseded by the objdiff golden path. See `attic/orchestrator/README.md` for historical context. |
| `attic/extract_functions.py` | Archived. Legacy helper that split old `texttmp.s` into per-function files; superseded by splat per-function output. |

## Common commands

```bash
# build target + base .o, then diff in objdiff
make all
python3 tools/generate_objdiff.py   # regenerate objdiff.json if layout changed

# progress
python3 tools/progress.py
python3 tools/progress.py --markdown

# raw decomp.me submission (Fallback 2)
python3 tools/decomp_match.py submit <func> asm/<sub>/<func>.s src/<sub>/<func>.c
python3 tools/decomp_match.py iterate <slug> src/<sub>/<func>.c

# brute-force (Fallback 1)
./tools/permuter_import.sh <func> src/<sub>/<func>.c
cd tools/decomp-permuter && python3 ./permuter.py nonmatchings/<func> -j8

# canonical byte-perfect build (WSL)
# (run inside WSL; sets up ext4 FS for reliable make)
bash tools/wsl/build_verify.sh

# full rebuild + verify (macOS / native)
python3 configure.py -c && make -j16 elf && make verify
```

## Notes

- **objdiff loop is the primary workflow.** `decomp_match.py` is for community sharing; `decomp-permuter` is the last-mile fallback for functions where exact compiler-quirk-correct C is elusive.
- **transmuter cleans stubs — it does not match.** Run it to reduce Ghidra noise before starting the objdiff loop; it will not tell you whether your C is correct.
- Compiler split: `make all` compiles C with `ee-gcc2.9-991111` (set `MATCH_CC`); `make elf` links with `mips64r5900el-ps2-elf-gcc` (modern ps2dev GCC). Both must be present for the full workflow.
- All repo-relative paths are relative to the project root. Toolchain env vars: `$PS2DEV`, `$PS2SDK`, `$MATCH_CC`.
