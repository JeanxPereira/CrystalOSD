# AI-assisted reverse engineering and binary-faithful reimplementation: landscape (2025-2026)

Compiled 2026-10-02 from web search plus page fetches. [V] = primary page fetched. [S] = search snippet only (not verified). [?] = unverified claim. Newest first within each section.

## 1. LLM decompilation and matching decompilation

- **Echo, learning-based matching decompilation via trusted back-translation** [V]. https://arxiv.org/abs/2609.18706 (2026-09-16). Searches for source whose recompiled assembly exactly matches the target under unknown compiler configs; rule rewriting, then neural, then reasoning refinement. Reports 2.43x more exact matches than the strongest baseline, 2.75x more than GPT-5.6 and 7.4x more than Codex on Mirai. Plug-in: the closed loop (candidate, compile, assembly diff, repair) is what N64/GBA agent setups do by hand. Relevant only if the original compiler (EE GCC 2.9x) is reproducible; for the clock module, behavior matters more than source matching.
- **When LLM Decompilers Recompile More and Preserve Less** [V]. https://arxiv.org/abs/2609.05370 (2026-09-04). Recompilable, test-passing LLM output still diverges from the original: 4.9% overall, up to 13% per system; one model raised build rate 75% to 90% while behavioral match fell 74% to 62%. Tool "Decompile-Diverge" uses fuzzing-based behavioral comparison. Plug-in: "it compiles and passes shipped tests" is not enough; our bit-compare verifiers must fuzz inputs beyond the probed ones.
- **Recompilation Is Not Enough: test-guided decompiled-C repair** [V]. https://arxiv.org/abs/2609.07201 (2026-09-07). Compiler/linker diagnostics repair, then semantic repair from tests. 91/104 Coreutils binaries (87.5%) recompiled and passed; 4 recompiled but failed behavior. Tests were pre-existing official ones. Plug-in: for us the emulator capture is the test source.
- **AutoDecompiler, RL multi-turn refinement** [V]. https://arxiv.org/abs/2606.16162 (2026-06-15). Multi-turn repair from compile errors, execution failures and test feedback, with regression-discouraging trajectory rewards. Beats single-turn at equal size; no numbers in the abstract. Plug-in: validates the loop design; training our own is not worth it.
- **LLM agent-assisted RE with quantitative readability metrics** [V]. https://arxiv.org/abs/2606.06838 (2026-06-05). Agents gamed metrics, producing structurally equivalent but less readable code. Lesson: gate plus independent sub-metrics; agents can also weaken a verifier to pass.
- **Mizuchi / "Can LLMs really do matching decompilation? 60 functions"** [V]. https://gambiconf.substack.com/p/can-llms-really-do-matching-decompilation (2026-03-10). Claude Sonnet 4.6 plus m2c and decomp-permuter: 74% match over 60 GBA/N64 functions, 88% run-to-run consistency, max 12 attempts; nearly half of matches on the first AI attempt; programmatic tools alone matched 7 functions on Animal Forest and none on Sonic Advance 3. Plug-in: cheap programmatic pass, then agent, then permuter maps to our verifier loop.
- **Using coding agents to decompile N64 games (Chris Lewis)** [V]. https://blog.chrislewis.au/using-coding-agents-to-decompile-nintendo-64-games/ . Human-led loop; tools given: build-and-diff, MIPS disassembly utilities, register-normalized object compare, asm-to-C line mapping. Findings: full assembly in context hurt, on-demand access helped; a dedicated directory with focused instructions beat root-level use with fewer tokens; agents are weak at arithmetic and struct offsets; parallel agents widen search. Plug-in: matches our "agents re-derive context" pain; build per-function work directories.
- **Not opened** [S]: "The long tail of LLM-assisted decompilation" (blog.adafruit.com, 2026-02-16); "Starting a decompilation project from zero: Claude Code and 51% of a GBA game" (gambiconf.substack.com); macabeus "Using AI for matching decompilation of an entire module" (Medium); a Claude Agent SDK runner plugin for decomp.me [?].
- **DecLLM** [S]. https://dl.acm.org/doi/pdf/10.1145/3728958 (2025-07). Iterative repair using static recompilation and dynamic runtime feedback as oracles; about 70% recompilation upper bound for off-the-shelf LLMs.
- **SK2Decompile** [S]. https://arxiv.org/pdf/2509.22114 (2025-09-26). Skeleton-then-skin two-phase decompilation. LLM4Decompile and ReF Decompile (2024-25) are the baseline lineage. All target x86 C benchmarks, not MIPS/VU.

## 2. Agentic RE frameworks and MCP servers

- **bethington/ghidra-mcp** [S]. https://github.com/bethington/ghidra-mcp . Claims 200+ tools (253 in one listing), GUI plugin and headless, lazy tool loading, batch operations. LaurieWired GhidraMCP is the popular small one (about 15 tools, 7k+ stars) [S]. GhydraMCP (multi-instance) and ReVa (chain-of-reasoning) also exist. Plug-in: lazy tool-group loading reduces token cost; our Ghidra MCP already has `load_tool_group`. Compare tool descriptions rather than adding servers.
- **mrexodia/ida-pro-mcp** [S]. https://github.com/mrexodia/ida-pro-mcp (about 12k stars): decompile, disassemble, xrefs, rename, debugging. **crowdere/Awesome-RE-MCP** [S] https://github.com/crowdere/Awesome-RE-MCP lists Binary Ninja and radare2 (26+ tools) servers.
- **Talos "Using LLMs as a reverse engineering sidekick"** [S]. https://blog.talosintelligence.com/using-llm-as-a-reverse-engineering-sidekick/ ; plus Medium/Hashnode "Agentic RE with Claude Code" write-ups [S]. Common pattern: agent renames and annotates in Ghidra; notes go in a markdown file.
- **hkmodd/ps2-recomp-Agent-SKILL** [V]. https://github.com/hkmodd/ps2-recomp-Agent-SKILL . Claude Code skill with R5900 ISA notes, PS2Recomp pipeline and syscall docs, helper scripts, a `PS2_PROJECT_STATE.md` state file, circuit breakers against token loops. Effectiveness unmeasured [?]. Plug-in: mine its R5900/MMI notes and the circuit-breaker idea; our `facts/` store is stronger.
- **Challenges and future directions in agentic RE systems** [V]. https://arxiv.org/html/2604.14317 (2026-04-15). Decompiled output costs too many tokens; recommends raw-binary analysis alongside decompilation, execution guardrails, timeout control, checks against endless tool chains.
- **Benchmarks** [S]: CrackMeBench https://arxiv.org/abs/2605.10597 (executable oracles, externally scored), SRE-Bench https://arxiv.org/html/2608.11469, CREBench https://arxiv.org/pdf/2604.03750, "Stop comparing LLM agents without disclosing the harness" https://arxiv.org/pdf/2605.23950. Takeaway: harness design matters as much as the model; scoring by executable oracle is the accepted standard, which is what our verifiers are. Strings in a binary are untrusted data (https://arxiv.org/pdf/2607.12507 on prompt-injection of RE agents), low risk for a first-party ROM.

## 3. Static recompilation and emulator oracles

- **ran-j/PS2Recomp** [S]. https://github.com/ran-j/PS2Recomp (GIGAZINE coverage 2026-01-30). Translates R5900 including MMI, FPU and VU0 macro mode to C++ (`ctx->r4 = ADD32(...)`); VU1 microcode support limited; experimental. Forks include ReInPS (Sly Cooper target). Plug-in: its instruction-semantics library is a cross-check for our JS verifiers; a function lifted to C++ could generate expected outputs automatically for integer and macro-mode code. FPU rounding fidelity unverified [?]; test against PCSX2 captures first.
- **RecompCore (Dolphin lockstep recompiler)** [V]. https://github.com/aharonahdoot/RecompCore . Lockstep mode re-runs every dispatch on the interpreter and compares full CPU state; reports 0 divergences over 37.7B dispatches and 239 differential oracle cases, and says this drove bit-exact FPU. Plug-in: template for us: per-function probe in PCSX2 (inputs, outputs, register file) compared against the lifted function across many frames, not one capture.
- **N64Recomp, XenonRecomp** [S]. Mature static recompilers; no emulator-oracle suite seen in the pages found. **No Bit Left Behind: brute-force lifting for fully static recompilation** [V, abstract only]. https://arxiv.org/pdf/2609.16423 (2026-09-16, UC Irvine): lifts every byte offset to avoid disassembly errors; no numbers extracted.
- **Differential conformance testing** [S]: xboxrecomp-style projects assemble snippets, lift, and run lifted C against real instructions. Applies to a per-instruction R5900/VU test generator (random operands through PCSX2 interpreter versus the JS model).

## 4. Automatic equivalence

- **Scalable Validation of Binary Lifters (PLDI 2020)** [S]. https://dl.acm.org/doi/pdf/10.1145/3385412.3385964 : per-instruction SMT validation, then composition. Applies to instruction-level verification of the JS model.
- **LLMLift, verified code transpilation** [S]. https://people.eecs.berkeley.edu/~sseshia/pubdir/llmlift-neurips24.pdf : LLM writes target plus proof, checked by a solver. Impractical for FP-heavy VU code; Z3 bit-vectors with round-toward-zero could work for short straight-line blocks [own inference, ?].
- **LLVM translation validation with LLMs and Lean** [S]. https://arxiv.org/pdf/2609.19583 (2026-09). Not opened.
- **Decompile-Diverge fuzzing** (section 1) is the most practical: fuzz both sides against an oracle.
- Mutation testing of verifiers: no primary source found. Own suggestion: mutate the JS verifier (swap rounding, off-by-one lane, drop a flag) and require failure on the stored capture.

## 5. FPU and GS exactness

- **PCSX2 FPU notes** [S]. https://forums.pcsx2.net/Thread-blog-Nightmare-on-Floating-Point-Street (403 when fetched); ps2tek https://psi-rockin.github.io/ps2tek/ . From snippets: no denormals (flushed to zero), rounding toward zero, overflow clamps rather than Inf/NaN, and FPU, VU and x86 can differ by a few bits in multiply; LSB behavior after rounding is "not well understood". Measure on captures, not docs. Plug-in: model per-unit rules (EE FPU vs VU MADD/accumulator) and test per instruction against PCSX2 interpreter output.
- **paraLLEl-GS** [V]. https://themaister.net/blog/2024/07/03/playstation-2-gs-emulation-the-final-frontier-of-vulkan-compute-emulation/ ; https://github.com/Arntzen-Software/parallel-gs (2024). Explicitly not bit-exact to hardware; found GSdx software renderer not hardware bit-accurate; texture-cache and feedback hazards need pixel-order emulation. Plug-in: do not treat any emulator's rasterized output as hardware truth at edge cases; use GS packet/register equality as the exact target, pixel equality as secondary.
- **PCSX2 GS dump format and GS Dump Runner** [S]. https://pcsx2.net/docs/advanced/gsdumprunner/ ; https://github.com/PCSX2/pcsx2/wiki/How-to-Create-a-GS-Dump . Dumps replay in PCSX2 and on a real PS2; the runner compares many dumps and outputs image diffs. Plug-in: we already have `watson_gs_dump`/`gsdump_parse`; the runner pattern gives an automatic pixel regression harness for the Vulkan port.

## 6. Cost and efficiency patterns

- **Don't Break the Cache** [V]. https://arxiv.org/pdf/2601.06007 (2026-01). Caching the static prefix (system prompt, tools, reference docs) cuts input cost in long-horizon agents; placement of dynamic content matters. No percentages extracted. Plug-in: keep CLAUDE.md, facts index and tool lists byte-stable at the front of each agent prompt.
- **TokenPilot** [S] https://arxiv.org/pdf/2606.17016 ; **Louis Bouchard, "Why we stopped compacting"** [S] https://www.louisbouchard.ai/context-engineering-2026/ : summarizing or rewriting history breaks the cache and bills full price. Isolated subagents reportedly used about 9K tokens versus 15K for an accumulating skills pattern [S, unverified]. Plug-in: prefer narrow subagents with a small fixed brief over compacting long sessions.
- **Lewis findings** (section 1): on-demand disassembly beat big listings; per-task directories saved tokens.
- Model tiering framed as "cost per accepted change" (https://wavect.io/blog/multi-model-ai-coding-agent-stack-2026/ [S]). Plug-in: cheap model for probe, capture and diff triage; strong model for writing and repairing verifiers.

## Ranked top 8 for our setup

1. **Auto-generated verifier skeletons from lifted code (medium).** Run ps2recomp or its semantics headers per function, wrap as an oracle, have the agent only reconcile differences with PCSX2 probes. Removes the biggest hand-work; gate with item 2.
2. **Per-instruction conformance suite against PCSX2 (medium).** Random operands through the interpreter for each FPU, MMI, VU0 and VU1 opcode used by the clock module versus the JS model. Fixes FP exactness; gives a trusted base (RecompCore and Binary Lifters pattern).
3. **Lockstep multi-frame probes plus input fuzzing (medium).** Probe inputs and outputs over hundreds of frames; perturb inputs via `write_memory` and re-run both sides (Decompile-Diverge pattern).
4. **Mutation test of verifiers (small).** A script perturbs each verifier and requires a failure; stops agents weakening checks.
5. **Build-id-keyed facts with machine-checked claims (small).** Each fact references its verifier and capture hash; a hook rejects unreferenced facts. Handles the two-binary problem.
6. **Per-function work directories with minimal briefs and a stable cacheable prefix (small).** One function, disassembly on demand, facts slice, verifier template.
7. **Model tiering (small).** Cheap subagents for capture and diff triage and mechanical edits; strong model for new verifiers and root cause. Track cost per verified function.
8. **GS dump regression runner (medium).** Packet-level compare first, pixel second, for the Vulkan port; pairs with existing gs_dump tools.

Not recommended: training our own decompiler models, SMT or Lean proofs of VU blocks (large, low return), adding more Ghidra MCP servers.

Unverified: all [S] items; caching percentages; ps2recomp FPU rounding fidelity; existence of any project doing mutation testing of RE verifiers (none found).
